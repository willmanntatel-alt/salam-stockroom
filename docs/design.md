# Planning model and module boundaries

The application is a local review tool for a small shop's stock worksheet.
It does not place orders, change inventory, connect to a marketplace, or query
an account. Every sample SKU and quantity is fictional.

## Units and formulas

All stock quantities are whole units. Weekly demand is an explicit user input,
not a forecast generated by this program. Prices and budgets are integer minor
units in a single currency; for example, 105 means 1.05 when the currency has
100 minor units. Currencies with a different scale are outside this version.

For each row:

1. `available = on_hand - reserved`.
2. `position = available + inbound`.
3. `reorder_point = ceil(weekly_demand * lead_days / 7) + safety_stock`.
4. `target = ceil(weekly_demand * cover_days / 7) + safety_stock`.
5. If `position <= reorder_point` and `target > position`, round
   `target - position` up to the next `pack_size`. Otherwise suggest zero.

Priority 2 means a replenishment is suggested and currently available stock is
less than estimated lead-time demand. Priority 1 is any other suggested
replenishment; priority 0 means no order. Priority is a transparent rule,
not a statistical score or a guarantee against stockouts.

## Budget behavior

Without a budget, allocate the suggested quantities. With a budget, visit
priority 2 and then priority 1 rows, preserving input order within each group.
Each row gets at most the suggested quantity and at most the number of whole
packs affordable from the remaining budget. An unaffordable pack is skipped so
later cheaper rows can still receive an allocation. Zero is a real zero budget.

This greedy policy is intentionally simple. It does not maximize profit,
optimize a knapsack, balance service levels, or account for delivery dates.
Inbound units count toward position regardless of arrival date. The urgent
flag still uses currently available stock, not inbound stock.

## Code map

| Module | Responsibility |
| --- | --- |
| `models.salam` | Inventory, suggestion, and plan value types |
| `numbers.salam` | Bounded numeric parsing, integer ceiling division, money display |
| `text_encoding.salam` | UTF-8 validity and BOM handling |
| `csv_reader.salam` | Strict quoted CSV state machine and row/field limits |
| `inventory.salam` | Header, duplicate SKU, field bounds, and cross-field validation |
| `planner.salam` | Reorder points, targets, and pack rounding |
| `budget.salam` | Stable priority allocation into a new plan |
| `text_report.salam` | Human review report and model limitations |
| `csv_report.salam` | Numeric export and spreadsheet formula neutralization |
| `arguments.salam` | Command-line option parsing and usage |
| `main.salam` | Read-only file boundary and orchestration |

The Python test harness compiles and calls the actual Salam executables; it
does not supply a replacement implementation to the application. Four Salam
test programs cover the modules. CLI tests cover malformed input, encoding,
budget semantics, quoting, and 240 deterministic randomized stock rows checked
against an independent Python integer oracle.

## Limits and errors

- UTF-8 with optional BOM, at most 2 MiB, 1000 data rows, and 256 bytes per CSV
  field. Blank lines are ignored. Quoted commas, escaped quotes, CRLF, and LF
  are handled. Quoted newlines are parsed, then rejected in SKU validation.
- SKU: trimmed, case-sensitive, 1–96 UTF-8 bytes, no ASCII controls; duplicates
  after trimming are rejected. Unicode normalization is not performed.
- Counts, pack size, and unit cost: 0–1,000,000. Pack size and unit cost must
  be positive. Days: 0–366. Coverage cannot be shorter than lead time.
- Reservations cannot exceed on-hand stock. Budget: 0–1,000,000,000,000.
- Every arithmetic operation and the total across 1000 maximum-sized rows fit
  signed 64-bit integers under these bounds. No floating-point money is used.
- Bad inputs fail the whole import, print an error to stderr, and exit 2.
  They never emit a partial plan. No input file is overwritten.
- CSV SKUs beginning with `=`, `+`, `-`, or `@` get a leading apostrophe to
  prevent spreadsheet formula execution. Other CSV fields are numeric.
  Text output preserves SKU spelling; exported plans are not inventory input.

No real stock dataset, private contact information, credentials, or financial
account is needed. Users must check assumptions before acting on a plan.
